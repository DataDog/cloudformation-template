# AWS Terraform WIF bootstrap (v1.0.0)

`terraform_wif_bootstrap.py` is the companion to the WIF-enabled Terraform configuration generated by web-ui. It uses the **released Datadog provider's native AWS WIF support**, not a custom provider fork. The generated configuration requires Terraform >=1.10, Datadog provider >=4.29,<5, and AWS provider >=6,<7.

The first-run dependency is intentional: AWS WIF mapping creation requires an existing Datadog AWS integration, but a provider configured for WIF cannot create that integration before the mapping exists. The helper resolves this in two phases:

1. Validate the current assumed AWS role, selected service account, org, existing mappings, and Terraform state. Existing integrations not owned by this generated state are not adopted.
2. Temporarily override the **same** Datadog provider configuration with a PAT supplied through an `ephemeral`/`sensitive` variable. Target only integration registration; defer optional forwarder dependencies.
3. Create/reuse the exact execution-role-to-service-account mapping. The AWS CLI role and Terraform's reported role must match, ignoring session names.
4. Remove the override, discard the PAT from subprocess environments, verify the real provider's WIF authentication, and apply the complete configuration normally.

No provider alias or state-provider migration is needed. The permanent provider uses only `org_uuid` and `cloud_provider_type = "aws"`. The unused bootstrap variable defaults to null; the secret itself never appears in HCL, tfvars, saved plans, state, or command arguments. Debug logging is disabled while the helper runs. Future operations use normal `terraform plan`, `apply`, and `destroy` with the same AWS execution role and no PAT.

### Usage and recovery

- Save the generated HCL in a new configuration and use a shared AWS credential chain/profile for both providers. Do not configure different provider-specific credentials/assume-role settings, IAM-user credentials, or the integration role managed by this configuration.
- Run the integrity-checked command from web-ui. The helper uses Python's standard library, Terraform, and AWS CLI. It prompts for the PAT without echoing it. CI may supply `DD_BOOTSTRAP_PAT` as a secret and explicitly opt into `--auto-approve`; the default is interactive plan review.
- The helper refuses existing override files and `TF_CLI_ARGS` overrides. It never overwrites them. If interrupted, the temporary override is removed; if someone edited that file while it was running, it is preserved with an explicit cleanup error.
- If initial mapping setup fails, the registered integration remains tracked by Terraform. Re-run bootstrap with a fresh PAT to resume; no unrelated integration or mapping is replaced.
- The WIF mapping is retained outside Terraform state. Destroy resources before revoking it or disabling the mapped service account. Changing the AWS execution role requires an explicit mapping change; role session-name changes do not.
- Optional log-forwarder/agentless modules still use an organization API key for **telemetry intake**. WIF replaces Terraform's API authentication, not those intake credentials.

### Validation

```sh
python -B -m unittest terraform_wif_bootstrap_test -v
# Optional: use installed released providers from a Terraform initialization.
TERRAFORM_WIF_INTEGRATION_BINARY="$(command -v terraform)" \
TERRAFORM_WIF_PROVIDER_MIRROR="/path/to/initialized/.terraform/providers" \
python -B -m unittest terraform_wif_provider_integration_test -v
```

The provider integration test uses real Terraform and Datadog 4.29.0/AWS 6.x binaries against loopback-only fake services. It validates SigV4, revokes the PAT immediately after mapping creation, verifies WIF-only apply/destroy, rejects attempts to use the expired PAT, and checks saved plans/state for secret leakage. External network access is blocked during the protocol test. No real cloud resources or Datadog credentials are used.

`bash release.sh <bucket>` independently publishes the helper at `aws-terraform-wif/v1.0.0/terraform_wif_bootstrap.py`, using an atomic create-only S3 write. This release does not publish or change StackSet templates. The web-ui command pins both the version and SHA-256, so update the checksum whenever the helper changes. Publish the artifact before enabling `aws_terraform_setup_wif` (including Frontend Availability).
